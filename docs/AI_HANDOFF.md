## Current Automation Architecture
- Central policy/model defaults live in `.verity/config.yml`; default behavior is human-in-loop with automation disabled until explicitly enabled.
- GitHub issue/feedback sync is bidirectional and must use echo markers plus delivery idempotency.
- Coding/review workflows send their rendered prompt straight to Multra, which supplies repository context; Codex reads the checked-out repository directly. Requires `MULTRA_API_KEY` or `BLUESKY_API_KEY`. Feedback AI Agent sessions may pass an optional validated `model` workflow input; no override preserves the existing gateway/workflow default.- Runtime/bootstrap/workflow updates roll out through canary first, then Settings-driven PR promotion. No silent default-branch mutation.
- Monitor, command router, auto-fix, deploy, and rollout paths must stop on duplicates, no-diff attempts, same-failure fingerprints, paused projects, and attempt/budget limits.
